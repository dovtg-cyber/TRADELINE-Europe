# 05. API, данные, безопасность, GDPR, границы услуги

## 1. API (v1, JSON, HTTPS, сессия в HttpOnly-cookie)
| Метод и путь | Роль | Назначение |
|---|---|---|
| POST /v1/auth/register, /verify, /login, /logout, /forgot, /reset | все | Аккаунты, код на email, сброс пароля |
| POST /v1/research | client | Создать исследование (бриф). Ответ: `run_id`, статус |
| GET /v1/research/{id} | client (своё), reviewer | Отчёт с доказательствами |
| POST /v1/research/{id}/review | reviewer | Решение: approved / changed / rejected + комментарий |
| GET /v1/sources/{source_id} | client | Версия, ссылка, дата, контрольная сумма |
| GET /v1/acts/{doc_id}/status?on=YYYY-MM-DD | client | Legal Time Machine |
| POST /v1/workspace/docs, GET /v1/workspace/docs | client | Свои документы |
| POST /v1/workspace/docs/{id}/grant | client | Доступ конкретному reviewer |
| GET /v1/alerts | client | Уведомления об изменениях (этап 2) |
| POST /v1/admin/ingest/run, GET /v1/admin/registry | admin | Загрузки и реестр |
Каждый вызов проверяет роль и владельца; ответ «нет доступа» одинаков для «не существует» и «не ваше». Ограничение частоты запросов и квоты исследований на аккаунт.

## 2. Данные
Схема: `legal-api/db/schema.sql` (v2, **не запускалась на PostgreSQL**: проверить на тестовой базе). Ключевое: версии актов с пятью датами и контрольной суммой; `research_evidence`; `human_review`; `audit_log`; очередь `job` (SKIP LOCKED); row-level security для документов и исследований клиента.

## 3. Безопасность
- Пароли: Argon2/bcrypt; email подтверждён кодом; блокировка перебора.
- Роли client/staff/reviewer/admin; reviewer видит документ только по явному разрешению клиента.
- Изоляция: проверка в приложении (`app/workspace.py`, 6 тестов) и в БД (RLS); приложение подключается ролью без BYPASSRLS.
- Секреты только в переменных окружения Render; ключ модели не попадает в браузер.
- Файлы клиентов: диск/объектное хранилище в ЕС, шифрование при хранении, срок хранения (`delete_after`).
- Резервные копии и проверка восстановления; неизменяемый журнал аудита.
- Раскрытие ИИ в интерфейсе. По материалам юридических обзоров, обязанность сообщать пользователю о взаимодействии с ИИ (ст. 50 AI Act) применяется с 02.08.2026, а требования к «высокорисковым» системам (Annex III) отложены до 02.12.2027 (Digital Omnibus: Парламент 16.06.2026, Совет 29.06.2026). Источники вторичные (law-firm): подтвердить по тексту Official Journal и у юриста; относится ли юридический ассистент к высокому риску, нужно решить с юристом.

## 4. GDPR/RODO (чек-лист, ждёт юриста)
Роли (администратор / процессор), основание обработки, договор об обработке данных с провайдером модели и хостинга, запрет обучения на данных клиента, список субпроцессоров, регион ЕС, срок хранения и удаление, права субъектов данных, оценка риска (DPIA), уведомление об инцидентах. Документы клиентов содержат данные третьих лиц.

## 5. Границы услуги (решение владельца и юриста до запуска)
1. Информационное исследование или юридическая консультация? В Польше профессиональная юридическая помощь регулируется (адвокаты, radcowie prawni): **не проверено в этом запуске**, нужен польский юрист.
2. Кто подписывает заключение: Expert Review человеком с нужным статусом.
3. Текст оговорок: не юридическая консультация, возможны ошибки, проверка высокорисковых операций специалистом, дата проверки законодательства.
4. Страхование профессиональной ответственности; условия оказания услуг.
5. Для высокорисковых операций система показывает требование проверки специалистом и не выдаёт «чистый» вывод.
