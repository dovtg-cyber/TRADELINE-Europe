# TRADELINE Legal Intelligence: оценка предложения и план

> Полное ТЗ, архитектура, реестр источников, безопасность и MVP: папка `docs/legal/` (01–06, журнал `PROGRESS.md`).

Принцип продукта: **Evidence first. Никаких юридических выводов без проверяемого источника.**
Модель не является источником права: она читает найденные нормы, а сервер проверяет каждое утверждение.

## 1. Что в предложении верно и остаётся
- AI не источник права; ответ строится только на найденных официальных текстах.
- Каждое существенное утверждение имеет источник, статью, цитату и дату редакции.
- Проверка актуальности по дате операции («Legal Time Machine»): дата принятия, публикации, вступления в силу и утраты силы хранятся отдельно.
- Если оснований недостаточно, система отказывается от вывода и называет недостающие данные.
- Начать с EU и Poland, архитектуру сделать расширяемой.
- Изоляция данных клиентов: каждый запрос к рабочему пространству фильтруется по пользователю.

## 2. Что я бы изменила (проверено поиском в ноябре 2026)
| В предложении | Что на самом деле / что делать |
|---|---|
| Бесплатный PostgreSQL на Render на старте | Бесплатная база Render удаляется через 30 дней (14 дней на апгрейд, потом удаление), 1 ГБ, без бэкапов. Для работы клиентов нужен платный тариф (от ~$6/мес). |
| Бесплатный веб-сервис | Засыпает через 15 минут простоя, файловая система временная (загрузки пропадают). Минимум платный Starter (~$7/мес). Для файлов клиентов нужен диск или объектное хранилище. |
| Redis + Celery с первого дня | Не нужно на старте. Фоновых воркеров бесплатных нет. Достаточно ночной задачи (cron) и обычного процесса. |
| Парсить TARIC | Страницы консультации TARIC, по описанию стороннего инструмента, исключены политикой robots от автоматического доступа. Использовать официальные ежемесячные выгрузки (raw data) и проверить условия лично. |
| Консолидированный текст EUR-Lex как «закон» | Консолидированные версии не имеют юридической силы, аутентичен только текст Official Journal. Хранить обе версии с пометкой. |
| «Проверка актуальности автоматом» | Консолидация в EUR-Lex выходит с задержкой (дни–недели). Система должна показывать «дата последней консолидации» и предупреждать о возможном отставании. |
| Конкуренты (Harvey, Casetext и др.) | Не копировать. Ниша: ВЭД, таможня, налоги и логистика ЕС–Польша–Китай, с доказательной проверкой и вашей экспертной проверкой. |

## 3. Реальные источники данных
- **EU**: EUR-Lex через публичный сервис CELLAR (SPARQL и REST, без ключа). Тексты: `publications.europa.eu/resource/celex/{CELEX}`.
- **Польша**: публичный Sejm ELI API (`api.sejm.gov.pl/eli`): Dziennik Ustaw и Monitor Polski, метаданные, статус, ссылки между актами, текст HTML/PDF. У старых актов PDF бывает без текстового слоя.
- **TARIC**: ежемесячная официальная выгрузка (см. выше).
- Заготовки загрузчиков: `legal-api/ingest/`. В этой среде они **не запускались** (нет сети): поля ответов нужно проверить на реальных запросах.

## 4. Этапы
**Этап 0, уже в сайте.** Страница Legal Intelligence, структурированная заявка (вопрос, юрисдикции, маршрут, происхождение, код CN/TARIC, дата операции, роль), автоматическое определение недостающих данных, отправка заявки вашим специалистам, ответ отчётом-файлом через кабинет. Ничего не выдаётся за юридический вывод.

**Этап 1. Сервер.** Аккаунты, база PostgreSQL, файлы, настоящая почта (код подтверждения, уведомления), разграничение доступа. Без него нельзя запускать для клиентов.

**Этап 2. База знаний EU + PL.** Загрузка актов из CELLAR и Sejm ELI с хранением каждой редакции, контрольной суммы, даты получения; разбор по статьям; полнотекстовый поиск (pgvector позже). Схема: `legal-api/db/schema.sql`.

**Этап 3. Ассистент + проверка.** Модель по API, получающая только найденные фрагменты. Ядро проверки уже написано и протестировано: `legal-api/app/verification.py` (существование источника, дословная цитата, редакция действует на дату, целостность текста). Перед запуском нужен оценочный набор: 50–100 вопросов с ответами, проверенными юристом, и метрики (доля подтверждённых утверждений, доля отказов, найденные ошибки). Полной достоверности гарантировать нельзя: исследование Стэнфорда нашло галлюцинации в 17–33% ответов коммерческих юридических AI-инструментов.

**Этап 4. Остальное.** Уведомления об изменениях законодательства, анализ документов и договоров, Expert Review (платная проверка вашим специалистом), расширение на Германию, Китай и другие юрисдикции.

## 5. Расходы (ориентир, цены проверять на момент запуска)
- Render: веб-сервис Starter ~$7/мес, PostgreSQL ~$6/мес, диск ~$0,25/ГБ/мес.
- API модели: по фактическому использованию, считать себестоимость одного исследования.
- Юрист для эталонных ответов и Expert Review.
- Домен и почтовый провайдер.

## 6. Границы услуги: вопросы, которые нужно решить до запуска
1. Информационное исследование или юридическая консультация? Это определяет ответственность и требования.
2. Кто ставит подпись под заключением (квалифицированный юрист/консультант)?
3. Защита данных клиентов (RODO/GDPR): где хранятся документы, договор с провайдером модели, запрет обучения на данных клиентов.
4. Текст условий и оговорок на сайте.
5. Страхование профессиональной ответственности.
Эти вопросы лучше обсудить с польским юристом до выхода на рынок.

## 7. Что в папке `legal-api`
Ядро проверки и порядок шагов (протестировано: 15 тестов), схема базы, адаптер модели с жёсткими правилами, загрузчики Sejm ELI и EUR-Lex (не запускались), заготовка API (не запускалась). Не написано: поиск по базе, реализация базы на PostgreSQL, плановые обновления, загрузчик TARIC, авторизация.
